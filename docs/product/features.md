# Daily Tech News — 产品说明

## 一、产品概览

Daily Tech News 是一个自动化的科技日报站。每天零点，系统会自动收集前一天（00:00 – 23:59）全球科技领域的真实新闻，调用 Agnes 模型进行归纳与撰写，并输出一份 MDX 格式的文档。用户每天访问站点即可读到"昨天发生了什么"，也可以随时回溯任意历史日期的日报。

- 站点名称：Daily Tech News
- 内容语言：英文（科技媒体语境），界面文案为英文排版
- 更新节奏：每日 00:00（Asia/Shanghai）自动生成前一日日报
- 内容形态：`content/YYYY-MM-DD.mdx`
- 部署形态：GitHub Pages 静态站点（无后端运行时）

## 二、核心功能

### 1. 今日速览（首页 `/`）
- 展示最新一期日报的日期、编号、大标题、副标题与摘要
- 显示本期标签（AI / Chips / Policy / Space 等）
- 展示本期条目数量、生成来源（Agnes 模型或本地编排）与生成时间
- 直接内嵌日报正文，无需跳转即可读完全文
- 顶部倒计时：距离下一期日报发布还有多久

### 2. 历史归档（`/archive`）
- 按月份分组展示全部历史日报
- 每期显示日期、标题、摘要、标签与条目数
- 点击进入单期详情页

### 3. 单期详情（`/issue/:date`）
- 完整渲染该期 MDX 正文
- 展示元数据与主图信息
- 提供"上一期 / 下一期"导航
- 可查看该期 MDX 原始文档

### 3.1 就地展开简报（`:::brief`）
- 每条报道下方有"展开简报"按钮，点击后在原地展开，不会跳转离开页面
- 简报内容来自原文：夜间生成时抓取文章正文，再由模型提炼成 2-3 句摘要与 2-3 条要点
- 抓取失败时依次回退到订阅源摘要、再到条目元信息，保证展开后永远有内容
- 未配置模型密钥时，直接取原文开头的句子作为简报，站点依然可用
- 展开区下方保留"打开原站"的链接，需要看全文或核对来源时可直达
- 简报以 `:::brief` 块写进同一份 MDX，存档保持单文件自足

### 4. 自动生成（每日 00:00）
- 采集层：Hacker News（Algolia 搜索 API）+ TechCrunch / The Verge / Ars Technica RSS，按发布时间窗口过滤
- 摘要层：调用 Agnes API（`agnes-2.5-flash`）撰写 MDX
- 落盘层：写入 `content/YYYY-MM-DD.mdx`，含 YAML frontmatter
- 兜底：未配置 API Key 时，使用本地编排器生成结构一致的 MDX，内容仍为真实新闻
- 手动触发：`POST /api/digests/generate`，可指定日期补生成

### 5. 主题聚合（`/topic/:tag`）
- 首页与归档页的每个标签都可点击，进入该主题下全部日报的列表
- 主题页顶部保留全部主题，当前主题高亮，可直接横向切换到别的话题
- 标签名按规则转成地址片段（如 `Generative AI` → `/topic/generative-ai`），链接稳定可收藏
- 整行可点击进入单期详情，标签本身也能点进主题页，两者不冲突

### 6. 全站搜索（`/archive`）
- 归档页顶部搜索框，输入后即时在全部历史日报里查找
- 检索范围覆盖标题、副标题、摘要、标签、要点、数字速记与信源名称、网址
- 结果按相关度排序，命中词用高亮底色标出，并给出 1-3 段上下文摘录
- 顶部显示"匹配到 N 期"，点结果直达单期详情；清空搜索即回到按月分组的归档

### 7. RSS 订阅（`/feed.xml`）
- 构建期生成标准 RSS 2.0 订阅源，每期日报一个条目
- 条目含标题、链接、发布时间、唯一标识，正文为摘要加要点列表
- 页脚提供订阅入口，订阅源地址随站点路径自动适配

### 8. 趋势视图（`/trends`）
- 时间范围可切换，默认**近七天**，另有近三十天与全部，切换后所有图表与数字立即重算
- 自动刷新：每分钟重新拉取一次数据，切回标签页也会刷新，无需手动重载页面
- 手动刷新：按钮旁显示"更新于多久之前"，刷新期间图标转动
- 顶部四个数字：期刊总数、报道总数、主题数、信源数，均按所选范围统计
- 每日信源构成：堆叠柱图显示每天链接来自哪些媒体，悬停看当天明细，下方配灰度图例
- 标签频次：横向条形图显示每个主题出现在多少期里，点击直达主题页
- 话题走势：一列对应一期，实心格表示该主题当天出现，可直观看出常驻话题与单日新闻
- 信源分布：统计所选范围内链接来自哪些媒体及各自占比
- 数据按天分桶存储，窗口聚合在浏览器端完成，切换范围不需要重新构建站点

### 9. 明暗切换
- 纸白与纯黑双主题，纯灰阶配色

### 10. 结构校验（发布闸门）
- 每期文档写入前必须通过结构校验，不达标则中断发布，不会留下残缺内容
- 校验项：frontmatter 九个字段齐全、日期格式正确、`TL;DR` / `Signals` / `Sources` 三个段落存在且非空
- 数量下限：`TL;DR` 至少 3 条、`Signals` 至少 3 条、`Sources` 至少 3 个链接（"安静日"模板豁免）
- 正文不得残留代码围栏、开头客套话、占位文字，所有链接必须是完整网址
- 出现未预期的顶级段落会被标记出来，便于发现模型跑偏
- 模型输出不合规时**不会**回退到本地编排器，而是直接中止，避免问题被掩盖
- 网络或接口故障仍然回退到本地编排器，保证出稿不中断

## 三、用户故事

| 角色 | 场景 | 期望 |
|------|------|------|
| 科技从业者 | 早上通勤时打开站点 | 5 分钟读完昨天最重要的科技要闻 |

## 四、页面结构

```
/               落地页 — 展示主页：Vgpu 单色几何场主视觉 + 三个入口
/today          今日 — 最新一期日报全文
/archive        归档 — 全部历史日报，按月分组，可全站搜索
/issue/:date    详情 — 指定日期的日报全文
/topic/:tag     主题 — 同一标签下的全部日报

```

## 五、数据模型

### MDX 文档（`content/YYYY-MM-DD.mdx`）

```yaml
---
date: 2026-08-28
title: "Chips, Chatbots and a Courtroom"
subtitle: "The day the AI industry argued with itself"
summary: "一段 2-3 句的当日速写"
tags: ["AI", "Semiconductors"]
itemCount: 12
source: agnes          # agnes | local
model: agnes-2.5-flash
generatedAt: "2026-08-29T00:00:12+08:00"
---
```

正文结构：

```
## TL;DR            — 3-5 条要点
## Signals          — 分条目的深度叙述（### 1. 标题）
## By the Numbers   — 数字/指标速记（可选）
## Sources          — 信源清单
```

### API 返回

| 字段 | 说明 |
|------|------|
| `date` | 日报日期 `YYYY-MM-DD` |
| `title` / `subtitle` / `summary` | 文案 |
| `tags` | 标签数组 |
| `itemCount` | 条目数 |
| `source` | `agnes` 或 `local` |
| `model` | 使用的模型 |
| `generatedAt` | 生成时间（ISO） |
| `content` | MDX 正文（不含 frontmatter） |

## 八、GitHub Pages 静态部署

Daily Tech News 默认以静态站点形式发布到 GitHub Pages，前端不再依赖 Express 后端，而是读取构建时生成的 JSON 静态数据。

### 8.1 架构拆分

- **内容生成**：`.github/workflows/daily-digest.yml` 在每日 00:00（Asia/Shanghai）触发，执行 `pnpm digest` 生成新的 `content/YYYY-MM-DD.mdx` 并提交到仓库。
- **站点构建**：`.github/workflows/deploy.yml` 在 `content/` 或前端代码变动后触发，先运行 `pnpm verify` 做结构校验（不通过即中断），再运行 `pnpm build:static` 把 MDX 编译为 JSON，最后运行 `pnpm build:pages` 打包 React 并预渲染路由。
- **写稿校验**：`.github/workflows/daily-digest.yml` 生成时即校验，模型输出不合规会中止，不会提交残缺文档。
- **发布交接**：提交成功后主动唤起发布流程。用仓库内置令牌推送的提交不会触发其他流水线，所以这一步不能省略。
- **定时兜底**：发布流程另有一道零点二十五分的定时触发，即使交接失败或漏跑，当天内容仍会更新上线。
- **静态数据**：生成后的 JSON 放在 `frontend/public/data/`，包含 `index.json`、`status.json`、`search.json`（搜索索引）、`trends.json`（趋势聚合）与每期的 `issue/<date>.json`。

### 8.1.1 两条流水线的衔接

```
00:00  写稿流水线启动
       ├─ 采集新闻 → 模型撰写 → 结构校验（不通过则中止并告警）
       └─ 提交 MDX → 主动唤起发布流程
00:25  发布流水线（兜底定时，可重复执行）
       ├─ pnpm verify      结构校验，不通过即中断发布
       ├─ pnpm build:static  编译为静态 JSON
       └─ pnpm build:pages   打包并预渲染 → 发布上线
```

两条流水线互相独立：写稿失败不会发布半成品，发布成功与否也不影响稿件入库。

### 8.2 预渲染路由

`scripts/build-routes.mjs` 会把 React 路由预渲染为静态 HTML：

| 路由 | 输出目录 |
|------|----------|
| `/` | `dist/index.html` |
| `/archive` | `dist/archive/index.html` |
| `/trends` | `dist/trends/index.html` |
| `/issue/:date` | `dist/issue/<date>/index.html` |
| `/topic/:tag` | `dist/topic/<tag>/index.html` |

同时生成 `.nojekyll`、`sitemap.xml` 和 `feed.xml`（后两者需要配置 `SITE_ORIGIN`）。

主题目录名必须与前端 `src/lib/topics.ts` 的标签转写规则一致，脚本 `scripts/build-routes.mjs` 里保留了一份同名实现并注明耦合关系，改动标签规则时两处要同步修改。

### 8.3 仓库级配置

1. 在 GitHub 仓库的 **Settings → Pages → Source** 选择 **GitHub Actions**。
2. 在 **Settings → Secrets and variables → Actions** 添加 `AGNES_API_KEY`（可选；未配置时使用本地编排器）。
3. 站点默认使用仓库名作为子路径（如 `/<repo>/`），由 `VITE_BASE` 环境变量注入。

### 8.4 本地命令

```bash
cd /workspace/backend && pnpm verify         # 校验全部日报结构（不通过则退出码 1）
cd /workspace/backend && pnpm build:static   # 生成 frontend/public/data/*
cd ../frontend && pnpm build:pages           # 打包并预渲染
```

## 九、字体与加载体积

站点不依赖外部字体 CDN，所有字体文件都通过 `frontend/scripts/build-fonts.py` 在构建期预处理。

### 9.1 字体按"声音"拆分

Recursive 上游是五轴可变字体（约 298 KB 一个子集）。设计系统只把它当两种声音用，于是分别烘焙成两个家族，而不是让一个文件背下所有轴：

| 家族 | 轴 | 拉丁子集体积 |
|------|-----|---------|
| Recursive Display（标题） | `MONO` 0、`CASL` 0.45，`wght` 500–720 可变 | 48 KB |
| Recursive Mono（小标签、等宽正文） | `MONO` 1、`CASL` 0.3，`wght` 固定 500 | 28 KB |
| 合计 | | **76 KB**（原三轴单文件 161 KB） |

等宽家族的每个轴都固定了，因此文件里完全没有 `gvar` 表——这是它只有 28 KB 的原因。

- **Golos UI**：按字符范围拆分，西里尔部分独立为按需下载文件；英文日报首屏只拉取拉丁子集，从约 29 KB 降到 17 KB。
- **Geist Pixel Square**：装饰等宽字体仅保留 Latin-1 与常用标点，从约 28 KB 降到 18 KB。

### 9.2 JavaScript 体积

- **移除动画库**：页面转场、滚动渐显、分组依次显现、简报展开原本由 framer-motion 驱动（压缩后 42 KB），现全部改为 CSS 动画加一个 30 行的 `useInView` 钩子。省下的体积约等于整个应用自身代码的五倍。
- **移除未使用依赖**：消息弹窗与提示气泡组件从未被真正调用，连同其依赖一并删除（压缩后约 4 KB）。
- **正文渲染按需**：`react-markdown` 仍是独立 chunk（压缩后 48 KB），但改为等读者滚动到距正文一屏之内时才拉取，而不是在首屏就预取。
- **框架单独成块**：React、路由与数据请求库打包为长期不变的 vendor 块，日常内容更新只让体积很小的应用块失效，回头客命中缓存。

### 9.3 实测结果

生产环境首页首屏总下载量：

| 阶段 | 总量 | 字体 | JS |
|------|------|------|-----|
| 优化前 | 564 KB | 356 KB | — |
| 第一轮（精简轴、路由级拆分） | 400 KB | 196 KB | 189 KB |
| 第二轮（拆分字体家族、移除动画库） | **265 KB** | **111 KB** | **138 KB** |

后续跳转页面只需 2–11 KB。重建字体：

```bash
cd /workspace/frontend && pnpm fonts
```

## 十、编辑式设计系统

针对"渐变太通用、视觉毛刺、布局别扭"的批评做了一次全面重构。创意方向由一段随机字符串推导：89% 字母对 11% 数字的构成、拒绝对称与重复（无回文、无连续字母串、重复最长仅 2 字符）、两段超长数字间隙等特征，落成以下原则——

### 10.1 布局：八栏左起编辑网格

- 全站不居中、不对称：正文占左 1–5 栏，元信息挂 7–8 栏，第 6 栏刻意留空。
- 章节标题、图表说明走"页边注"式两栏/三栏布局，图表横跨右侧五栏。
- 章节之间用整段"留白带"（5rem / 7rem）控制节奏，而不是零散的 margin。

### 10.2 色彩与发丝线

- 中性色统一带冷色微倾向（OKLCH 色相 258），整页读作"同一种墨"。
- 强调墨色只给数字与数据标记（计数、日期、百分比、焦点环），正文永远黑白。
- 所有边框为 1–2px 实色发丝线，明暗两套均为实色——半透明描边叠底产生的深浅接缝是此前"毛刺感"的主要来源，已全部消除。

### 10.3 间距与数字

- 间距标度只由 1 / 2 / 3 / 5 四个数派生。
- 小号数字统一用 Geist Pixel Square（`.num`），大号数字换用展示字重（`.num-lg`），均带表格数字特性；像素字体不放大使用。

### 10.4 动效

- 导航、排序、区间切换统一为"自左展开的下划线"，不再使用反色色块跳动。
- 滚动显现的触发条件由"可见比例"改为"底部预留 96px"——页面底部的高大区块即使被页脚挤压到可见比例不足，也必定会显现，杜绝内容永久隐形。
- 打印与无脚本环境下显现动画不吞内容；`prefers-reduced-motion` 全局兜底。

### 10.5 View Transitions：一套完整的形变体系

**瓷砖形变（前进）**——卡片与单期页之间，四件事共同保证：

- **数据路由器**：路由器升级为 `createBrowserRouter`——普通 `BrowserRouter` 下 `<Link viewTransition>` 会被静默忽略（这是此前转场"看起来没发生"的根因，逐帧 screencast 抓包确认后修复）。
- **悬停即取**：指针悬停行卡片时并行预热四样东西——期数数据（React Query prefetch）、单期页代码块、正文渲染块，以及路由级 lazy 的目标路由；点击时零网络等待。
- **路由 state 随行**：卡片把期数元数据塞进 router state，单期页首帧直接用 state 渲染完整 hero，等不到网络。hero 不做渐显——它是转场的落点。
- **瓷砖盖章**：点击瞬间给行标题盖上 `view-transition-name: issue-title`，浏览器把旧页标题与新页 hero 作为同一元素形变（400ms，`cubic-bezier(0.22,0.9,0.24,1)`）；新旧页面根节点各自 200ms 淡出 / 340ms 淡入；飞行中的瓷砖不带悬停下划线——那是列表里的手势，不是转场的一部分。

**瓷砖回落（逆向）**——从期页经头部导航回列表时，元数据经 NavLink 的 state 回传，列表里对应日期的那一行为转场借回同一个名字，hero 缩回它来的地方，而不是凭空淡出。名字只在转场进行中存在（`useViewTransitionState` 门控），不会与其他盖章冲突。

**重排形变（FLIP）**——排序与趋势区间切换不是淡出淡入，而是真正的位置迁移：

- `withMorphicTransition` 先同步给元素盖名（旧快照带名）、转场内更新状态（新快照同名）、动画结束后撤名；
- 排序时每行带 `row-<date>`、月份标题带 `month-<key>`，整组行块与月份标题滑向新位置；
- 趋势区间切换时柱体带 `bar-tag-*` / `bar-src-*`，在统计窗口之间迁移、伸缩；
- 所有形变组共用同一条 400ms 缓动；形变期间列表对重复点击免疫。

**路由级 lazy 全覆盖**——所有页面走路由级 lazy：代码块就位后导航（以及它的转场）才开始，新快照永远拍不到 Suspense 空壳。这是逐帧审计抓到的最严重毛刺（转场结束后整页空白 3 帧）的根因，已消除。

主题切换是从按钮自身生长的圆形揭示（460ms clip-path）。`prefers-reduced-motion` 下所有转场退化为直切。

逐帧验证：CDP screencast 以 60fps 抓取全部四类转场——正向瓷砖、逆向回落、排序滑移、区间迁移——零空白帧、hero 首帧到位、正文在形变结束前补齐。审计脚本保留在 `frontend/scripts/audit.py`。

### 10.6 圆润令牌

## 十一、落地页与 Vgpu 主视觉

`/` 是展示型落地页：大字排版、三个入口卡片（今日/归档/趋势）、最新一期横幅；今日期移至 `/today`，导航、悬停预载与预渲染清单同步更新。主视觉由 WebGPU shader（Vercel 开源的 vgpu 库）驱动。

### 11.1 单色几何场

全部元素与黑白编辑风同源：28px 细网格、140px 主网格与交点十字准星、45° 呼吸对角信号线、双圆盘（实线外环 + 虚线内环）与环上雷达刻度、横扫光带、胶片颗粒。shader 输出 premultiplied alpha 的墨色覆盖，纸色来自页面背景，墨色随主题翻转（浅色纸黑墨、深色纸白墨），排版侧叠加纸面纱保证标题对比度。

### 11.2 帧率纪律

- **DPR 钳制 [1, 2]**——surface 内建，高分屏至多渲染两倍物理像素；
- **滚出视口即停帧**——IntersectionObserver 调 `loop.stop()`，画布保留最后一帧，回视口无缝续播；标签页隐藏时 rAF 由浏览器自动停摆；
- **reduced-motion 单帧**——只渲染一帧定妆，永不进循环；
- **按需加载**——vgpu 仅在确认 `navigator.gpu` 后动态 import（约 57 kB gzip 的独立异步分块），不支持的老浏览器连库字节都不下载；
- **CSS 几何场兜底**——无 WebGPU 时落到同构图的 CSS 版本：网格/准星/对角线/双圆盘逐一对齐，扫描带是 transform 合成器动画，主线程零成本；
- **shader 无循环**——全屏一次乘加，DPR 2 下成本可忽略。

### 11.3 层序、实渲验证与审计

两轮像素级审计各抓到一个 bug，均已修复：

- **层序**——首拍发现负 z-index 把几何场压进页面不透明背景之后、整层不可见；改为纯 DOM 顺序成层（几何场 → 纸面纱 → 内容）。
- **坐标空间**——首次真实渲染时画布呈整幅纯色（浅色 flat 15、深色 flat 237，恰好是 shader 的两个 tone 值）：vgpu 的 `texelSize` 是纹素倒数（1/w, 1/h），曾被误当画布尺寸使用，坐标塌缩后所有网格/圆环判定恒为 1。修复为显式传 CSS 像素尺寸（画布尺寸 ÷ DPR），与 CSS 兜底的 28/140px 网格尺度严格一致。

实渲验证在无 GPU 沙箱内完成：有头 Chromium + Xvfb + SwiftShader Vulkan flags（无头模式会把 WebGPU 画布合成成黑块，属上游限制）。修复后落地页截图的画布区采样出上千种色值（浅色 1092、深色 688、移动端 8034），premultiplied 合成正确（coverage=0 处纸色透出）。帧率实测（SwiftShader 纯 CPU 光栅化，最严苛下界）：hero 静止约 21 fps、滚动中约 46 fps，滚出视口后 rAF 恒定 60.0 fps（p95 = p50 = 16.7 ms）——「滚出即停帧」纪律生效；真实 GPU 上这是一次全屏乘加，远在 vsync 预算之内。

48 组合像素审计（6 路由 × 4 视口 × 明暗）零缺陷；v12 全套 13 张截图以最终构建重拍，落地页三张均为真实 WebGPU 渲染。
